# Probability-Level Fusion of Meta-Information and Multimodal MRI/PET Radiomics

## Scope

This repository contains the public code for predicting 1p/19q codeletion and IDH mutation from separately modeled meta-information and multimodal MRI/PET Radiomics probabilities. It includes tumor-centered Radiomics extraction, leakage-aware repeated nested cross-validation, probability calibration, weighted averaging, logit stacking, statistical analyses, and figure and table generation. CNN, SSL, Grad-CAM, and feature-level fusion are outside this public release.

## Data availability

Patient-level clinical data, medical images, tumor-center coordinates, molecular labels, and patient-level Radiomics tables are not distributed because they are subject to institutional, ethical, data-governance, and confidentiality restrictions.

## Configuration

Edit `config.py` before execution. Set `TASK` to `IDH` or `1p19q`, and specify authorized local paths for the label table, tumor-centered image crops, tumor-center coordinates, and output locations. Do not commit private paths or patient data.

## Label and meta-information input

The label CSV contains one row per patient. Required identifiers and outcomes are `patient_id` (or `No`, converted to `patientNNN`), `IDH_mutation`, and `1p19q_codeletion`. The public dataset class reads only `Age`, `X`, `Y`, `Z`, `Calcification`, and `mismatch` as meta-information variables.

Calcification values `0`, `0.5`, and `1` are valid. The code `-1` is converted to missing. Within each training fold, the most frequent observed calcification value is learned and applied unchanged to the corresponding validation or test data. No missingness indicator is added.

## Radiomics extraction

MRI crops are clipped to the 1st–99th percentiles and standardized within each crop. MET and FDG are clipped to the 1st–99th percentiles; CHO is clipped to the 5th–95th percentiles. No logarithmic PET transformation is used in the reported configuration.

MRI features use fixed bin width 0.25 and PET features use fixed bin width 10.0. The extraction script runs the MRI and PET experiments separately, validates patient IDs and labels, and merges the feature tables column-wise into `RADIOMICS_CSV`. The YAML enables Original, LoG at sigma 0.5, 1.0, 1.5, 2.0, and 3.0, and Wavelet images with first-order, GLCM, and GLDM features. Wavelet feature names use the `wavelet-H` form, for example `ROI25_FLAIR_wavelet-H_firstorder_10Percentile`.

Run from the repository root:

```bat
python -m radiomics_extraction.extract_radiomics_probability_fusion
```

├── roi_coordinates/<numeric_patient_id>.txt

The extraction workflow writes experiment-specific CSVs, patient checkpoints, failure logs, manifests, summaries, generated YAML files, and the merged `radiomics_features.csv` configured by `RADIOMICS_CSV`.

## Probability-fusion analysis

Set `TASK` and `RADIOMICS_CSV` in `config.py`, then run:

```bat
python -m scripts.main_probability_fusion
```

The workflow evaluates meta-information only, Radiomics only, weighted averaging, and logit stacking using repeated stratified five-fold nested cross-validation with seeds 42–51. Preprocessing, imputation, feature selection, hyperparameter selection, calibration, fusion-candidate selection, and threshold selection are restricted to training data. Model-specific thresholds maximize balanced accuracy from 0.10 to 0.90 in increments of 0.01 using pooled outer-training OOF probabilities.

## Sensitivity analyses

The complete-case sensitivity analysis was generated by rerunning the same probability-fusion pipeline after excluding the four patients with missing calcification status. The corresponding Table S5 was assembled from the resulting standard pipeline outputs.

Table S1(b) was assembled from the standard probability-fusion outputs generated by separate MRI-only reruns using fixed MRI bin widths of 10.0, 1.0, 0.5, and 0.25.

## Statistical analysis and publication outputs

Run the statistical-analysis script against the root containing the six probability-fusion runs:

```bat
python -m analysis.jimaging_revision_analysis --root <RUN_ROOT> --output <OUTPUT_DIR>
```

Run the metadata audit with either a `patient_id` or `No` identifier column:

```bat
python -m analysis.metadata_completeness_audit data_not_included/labels.csv --outdir metadata_audit_output --expected-n 217
```

The statistical-analysis script generates quality-control reports, patient-level aggregation, paired bootstrap comparisons, Holm-adjusted p-values, calibration summaries, manuscript tables, supplementary tables, and figures as CSV, PNG, PDF, JSON, and text outputs. It does not create an Excel workbook and does not require `openpyxl`.

## Synthetic examples

`examples/synthetic_labels.csv` and `examples/synthetic_radiomics.csv` use matching `patient_id` values and molecular labels. All values were generated solely for this repository and were not derived from study participants. They illustrate expected schemas and file linkage only. Four rows cannot run the five-fold nested cross-validation workflow and cannot reproduce reported results.
